macsetup stops restating the rn-forge home's `PATH` and `fpath` lines: the
installer honours an inherited `$RNF_HOME`, and the rendered profile sources the
home's `env.sh`, falling back to its own lines on a host without one.
[Port plan, Phase 0](../../python-tool-port.md#phase-0-macsetup-sources-the-rn-forge-homes-envsh).

## S1.1.1 — install.sh honours RNF_HOME; document env.sh

**State:** Closed (2026-11-21)

**Acceptance:**

- `shell/install.sh` sets `RNF_HOME="${RNF_HOME:-${HOME}/.rn-forge}"` and passes
  it to shkit's installer.
- The spec sandbox pins `RNF_HOME`, so an exported value never points test
  installs at the real home.
- `docs/architecture/runtime-layout.md` lists `env.sh` and says the home's
  `env.sh` owns `PATH` and `fpath`.
- `RNF_HOME=/nonexistent-guard mise run verify` passes.

## S1.1.2 — the shared profile sources env.sh

**State:** Active

**Acceptance:**

- `macsetup-config`'s `shared/profile.zsh` sources `${HOME}/.rn-forge/env.sh`
  when it exists, and otherwise exports `RNF_HOME`, prepends `bin/` to `PATH`
  and appends `completions/` to `fpath`; the oh-my-zsh block no longer appends
  `completions/` itself.
- The change is published with `rnfmac config push`.
- After `rnfmac sync`, a new zsh lists `~/.rn-forge/completions` on `fpath` once
  and `rnfmac <TAB>` completes; with `env.sh` moved aside, `PATH` and
  completions still work through the fallback.

The edit is made in the `macsetup-config` checkout but not yet committed or
pushed.
