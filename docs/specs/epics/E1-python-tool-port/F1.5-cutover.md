The Python `rnfmac` becomes the shipped product: a small `bootstrap.sh` replaces
`shell/install.sh`, the shell payload and its tooling are deleted, shkit leaves
macsetup, and each host is migrated once.
[Port plan, Phase 4](../../python-tool-port.md#phase-4-cutover).

## S1.5.1 — bootstrap.sh

**State:** New

**Acceptance:**

- `bootstrap.sh` installs Homebrew if absent (with `--force`), then uv, then
  `rnfmac` from the latest tag, or from `--archive <file>`; it stays
  sourceable, with no `set -e` and no `exit`.

## S1.5.2 — retire the shell product and shkit

**State:** New · **Depends on:** S1.5.1

**Acceptance:**

- `shell/`, `tests/*_spec.sh`, `.shellspec`, `.shellcheckrc`, `.mise.toml`,
  `scripts/`, the shkit fixtures, the kcov job and the shell sections of
  `CLAUDE.md` are gone; nothing sources `shkit.sh`.
- `README.md` gives the bootstrap line and the `task` verbs.

## S1.5.3 — migrate each host

**State:** New · **Depends on:** S1.5.2

**Acceptance:**

- On each host: `rnfmac self install`, the old `$RNF_HOME/macsetup/v*` shell
  versions deleted by hand, then `rnfmac sync`; `config/` and `profile.zsh`
  untouched.

## Acceptance

- S1.5.1, S1.5.2: on a fresh macOS user account, the bootstrap line, then
  `rnfmac system init` and `rnfmac sync`, give a working shell where
  `rnfmac <TAB>` and `kiln <TAB>` both complete; the same works with
  `--archive` while `githubusercontent.com` is blocked.
- S1.5.3: done by hand on every host.
