Every remaining shell command that changes the machine exists in the Python
`rnfmac`, on the Phase 2 patterns (`Runner`, `Layout`, findings), keeping each
shell invariant. The shell product stays the shipped `rnfmac` until F1.5.
[Port plan, Phase 3](../../python-tool-port.md#phase-3-port-the-commands-that-change-the-machine).

## S1.4.1 — rnfmac config pull, push and reset

**State:** Closed (2026-11-22)

**Acceptance:**

- `rnfmac config pull`, `push` and `reset` do what `config/pull.sh`, `push.sh`
  and `reset.sh` do, with the same messages and exit codes.
- `pull` carries uncommitted local changes across the update on a stash, as
  `update_config_checkout` in `config/lib.sh` does.
- pytest cases port every relevant example of their shellspec specs.
- `push` takes `[--message <text>]`, defaulting to the host name; an empty
  message is an error (exit 1). There is no `-m`: the import contract forbids
  `typer`, and `rn-forge-cli` declares no custom options (owner, 2026-11-22).

## S1.4.2 — rnfmac profile sync

**State:** Closed (2026-11-22)

**Acceptance:**

- `rnfmac profile sync` renders `profile.zsh`, installs the theme and
  keybindings from the packaged assets, and patches `.zprofile` and `.zshrc`
  as `profile/sync.sh` does.
- The `.zshrc` block lands before its `source $ZSH/oh-my-zsh.sh` line; both
  `.zprofile` and `.zshrc` get their own copy; a second run changes nothing.
- The theme and keybindings are copied from the package assets, replacing a
  theme symlink rather than writing through it; changed files are backed up to
  `$RNF_HOME/backup/macsetup/<name>_<timestamp>` unless identical to the
  newest backup of that name.
- pytest cases port every relevant example of its shellspec spec.

## S1.4.3 — rnfmac brew sync

**State:** Closed (2026-11-22)

**Acceptance:**

- `rnfmac brew sync` does what `brew/sync.sh` does, with the same exit codes:
  `brew bundle install` then `cleanup` against the config checkout's
  `hosts/<host>/Brewfile`, then `brew list`; the first failing `brew` command
  ends it with that command's exit code.
- `Runner.stream` runs a command attached to the terminal and returns its exit
  code (127 when it cannot start); `FakeRunner` scripts it like `run`.
- pytest cases port every relevant example of its shellspec spec.

## S1.4.4 — rnfmac brew relay

**State:** Active · **Depends on:** S1.4.3

**Acceptance:**

- `rnfmac brew relay [--regen]` does what `brew/relay.sh` does, reading the
  patches and strategy class from the packaged assets.
- Every run resets `/opt/homebrew` to clean and re-applies the packaged patches
  fresh; nothing is cherry-picked from a stored commit.
- pytest cases port every relevant example of its shellspec spec.

## S1.4.5 — rnfmac system sync and system init

**State:** Active

**Acceptance:**

- `rnfmac system sync` installs the configured runtime versions as
  `system/sync.sh` does: a version with no match, or one that fails to
  install, is logged and skipped, the rest still runs, and the command exits 1
  at the end if anything was skipped. There is no hard-coded fallback pin.
- `rnfmac system init [--force]` installs oh-my-zsh and its plugins, nvm and
  SDKMAN as `system/init.sh` does; Homebrew and uv are left to the bootstrap.
- Both have no tests, by convention, and the coverage exclusion names their
  modules; they are verified by hand on a host.

## S1.4.6 — rnfmac sync

**State:** New · **Depends on:** S1.4.1, S1.4.2, S1.4.3, S1.4.5

**Acceptance:**

- `rnfmac sync` runs `config pull` first, then the rest in `sync.sh`'s order.
- When the config checkout was absent, it clones it and stops without applying
  anything.
- pytest cases port every relevant example of its shellspec spec.
