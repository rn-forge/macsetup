A kiln `python-tool` scaffold, `rn-forge-macsetup`, lives beside the shell
product, which moves from `src/` to `shell/` and stays the shipped `rnfmac`.
[Port plan, Phase 1](../../python-tool-port.md#phase-1-the-kiln-scaffold-beside-the-shell-code).

## S1.2.1 — render the scaffold and move the shell payload

**State:** Closed (2026-11-21)

**Acceptance:**

- kiln renders a `python-tool` with docs profile `mkdocs` and Sonar on, pinned
  by `[kiln] ref`; `task validate` passes.
- The shell payload lives under `shell/`, and `scripts/build.sh`, `.mise.toml`,
  Sonar and the shell CI workflow point at it.
- The hand-written docs are merged into kiln's `docs/` structure.

## S1.2.2 — ToolProduct and packaged assets

**State:** Closed (2026-11-21)

**Acceptance:**

- `ToolProduct` is `name="macsetup"`, `repo="rn-forge/macsetup"`, linking
  `bin/rnfmac` and `completions/_rnfmac`; `self` and `version` come from
  tooling.
- The zsh theme, keybindings and Remote Relay assets ship under
  `src/rn_forge/macsetup/assets/`, read through `importlib.resources`, and
  `tests/test_assets.py` fails when a copy differs from `shell/`.
- Under a scratch `RNF_HOME`,
  `rnfmac self install --archive <git archive of HEAD> --version 0.0.0` links
  `bin/rnfmac` and `completions/_rnfmac` through `current`,
  `rnfmac self doctor` exits 0, and a pre-existing `macsetup/config/` and
  `profile.zsh` survive both the install and `rnfmac self cleanup`.
