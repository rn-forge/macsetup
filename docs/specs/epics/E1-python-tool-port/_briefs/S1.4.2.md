# S1.4.2 — rnfmac profile sync

Brief for
[S1.4.2](../F1.4-machine-changing-commands.md#s142-rnfmac-profile-sync), at
`143b1a6` (line references) on branch `feature/python-tool-port`.

## Goal

Port `shell/commands/profile/sync.sh` to `rnfmac profile sync`: render
`profile.zsh`, copy the host Brewfile, patch `.zprofile` and `.zshrc`, set
`ZSH_THEME`, and install the zsh theme and keybindings from the packaged assets.
The files it writes must be byte-identical to the shell version's.

## Settled

- **Invariant (CLAUDE.md):** the `.zshrc` block goes *before* the
  `source $ZSH/oh-my-zsh.sh` line; `.zprofile` and `.zshrc` each get a copy.
- **Rendering** reuses `render_profile` in `services/profile_check.py` (already
  byte-for-byte the shell's `render_profile_content`). Do not copy it.
- **Theme and keybindings are copied from package assets**
  (`rn_forge.macsetup.assets.read_asset("profiles", "shared", <name>)` — check
  the actual asset path under `src/rn_forge/macsetup/assets/`), not symlinked:
  the Python install has no stable `current/profiles/` path. The theme
  destination is today a symlink into the shell install, so **unlink it before
  writing** — writing through it would overwrite the shell install's copy.
  Lead (reviewer) decision, 2026-11-21, under the owner's go-ahead for Phase
  3\.
- **Backups** go to `$RNF_HOME/backup/macsetup/<name>_<YYYYmmddHHMMSS>`, skipped
  when the file is identical to the newest existing backup of that name. (The
  shell's `ls -t … || true | head -1` compares against all of them because of
  operator precedence; comparing against the newest is the intended
  behaviour.)
- Messages: success "Profile synced successfully !" at the end; the missing host
  profile and missing Brewfile cases are errors, exit 1, with the shell's
  text.

## Current behaviour

`shell/commands/profile/sync.sh`, in execution order:

1. `render_profile` (line 98): no `config/hosts/<host>/profile.zsh` → "no
   profile for host '<host>' — create hosts/<host>/ in macsetup-config", exit
    1. Else write the rendered profile to `$RNF_HOME/macsetup/profile.zsh`;
       *then* no `hosts/<host>/Brewfile` → "no Brewfile for host '<host>' —
       create hosts/<host>/Brewfile in macsetup-config", exit 1 (the profile is
       already written). Else copy the Brewfile to
       `$RNF_HOME/macsetup/Brewfile`.
1. `update_zprofile` (line 49): back up; no marker line
   (`#################### macsetup`, `Layout.marker`) → append marker and
   `Layout.source_line` (two lines, each newline-terminated); marker but no
   source line → append the source line only. A missing `.zprofile` is
   created.
1. `update_zshrc` (line 72): back up; no marker → insert, before every line
   matching `^source $ZSH/oh-my-zsh\.sh`, the marker, the source line and an
   empty line (awk prints `line "\n"`, so: marker\\n source\\n \\n). No match
   → no change. A missing `.zshrc` stays missing (awk fails on it under
   `set -e`; treat a missing `.zshrc` as nothing to patch).
1. Theme (line 120): link the theme into
   `$HOME/.oh-my-zsh/custom/themes/rohitnarayanan.zsh-theme`; take the value
   after the first `=` of the first `^export ZSH_THEME=` line in the rendered
   profile (empty when none); back up `.zshrc`; replace every `^ZSH_THEME=.*`
   line in `.zshrc` with `ZSH_THEME=<value>`.
1. Keybindings (line 131): back up, `mkdir -p $HOME/Library/KeyBindings`, copy
   `DefaultKeyBinding.dict` there.

Python today: `commands/profile.py` registers only `check`;
`rnfmac profile sync` exits 2 "No such command 'sync'".

## Change

- **Change:** new `src/rn_forge/macsetup/services/profile_sync.py` (one function
  per step above, plus `profile_sync(layout, host)`); register `sync` on
  `profile_app` in `commands/profile.py`; add it to `docs/guides/commands.md`
  beside the Python `profile check` entry. Put any new path (backup dir, theme
  and keybindings destinations) on `Layout`.
- **Leave alone:** `render_profile` and `profile_check` behaviour.

## Tests first

New `tests/test_profile_sync.py`, porting `tests/commands/profile/sync_spec.sh`
(the examples about the installed shell dist do not apply; the rest do). Use
`sandbox` and `rnfmac`. Each fails before the change with exit 2.

- `test_renders_shared_and_host_profile_and_copies_the_brewfile`: rendered file
  equals `render_profile(...)`; Brewfile copied.
- `test_patches_zprofile_and_zshrc`: both have marker and source line; in
  `.zshrc` the block is before `source $ZSH/oh-my-zsh.sh`, exact bytes
  `marker\nsource …\n\nsource $ZSH/oh-my-zsh.sh\n`.
- `test_second_run_changes_nothing`: run twice; one marker in each rc file, and
  every written file byte-identical after the second run.
- `test_completes_an_old_zprofile_block_missing_the_source_line`.
- `test_a_missing_host_profile_is_an_error`: exit 1, "no profile for host
  'testhost'", nothing written.
- `test_a_missing_brewfile_is_an_error_after_rendering`: exit 1, profile
  written, no Brewfile copied.
- `test_sets_zsh_theme_from_the_rendered_profile`: seed `export ZSH_THEME="x"`
  in the host profile and `ZSH_THEME="robbyrussell"` in `.zshrc`; afterwards
  `.zshrc` has `ZSH_THEME="x"`.
- `test_installs_theme_and_keybindings_from_assets`: the bytes equal the
  packaged assets.
- `test_replaces_a_theme_symlink_without_writing_through_it`: make the theme
  destination a symlink to another file under `tmp_path`; afterwards that file
  is unchanged and the destination is a regular file.
- `test_backs_up_changed_files_once`: a second run with no change adds no
  backup; changing `.zshrc` between runs adds one.
