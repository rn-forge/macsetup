# S1.4.6 — rnfmac sync

Brief for [S1.4.6](../F1.4-machine-changing-commands.md#s146-rnfmac-sync), at
`2ddf2aa` on branch `feature/python-tool-port`.

## Goal

Port `shell/commands/sync.sh` to the top-level `rnfmac sync`: pull config, then
profile sync, then brew sync and system sync — reusing the Phase 3 commands
already in the package.

## Settled

Lead (reviewer) decisions, 2026-11-22, under the owner's go-ahead for Phase 3:

- **Invariant (CLAUDE.md):** `sync` runs `config pull` first. When the config
  checkout was absent before the pull, the pull clones it and `sync` stops
  without applying anything: info "configuration checkout created but not
  applied — run 'rnfmac sync' to apply it", exit 0.
- **Registration:** `sync` is top-level, so it is declared in
  `.rn-forge/kiln/config.toml` as a `[[cli.commands]]` entry (`name = "sync"`,
  `target = "rn_forge.macsetup.commands.sync:sync"`), placed first, then
  `task kiln:apply` regenerates `cli.toml`. Never hand-edit `cli.toml`.
- **Steps reuse the command functions**, in order: `commands.config.pull()`,
  `commands.profile.sync()`, then the profile environment (below), then
  `commands.brew.sync()` and `commands.system.sync()`. Their messages and exit
  behaviour are what `sync` prints and returns: an `AppException` or
  `SystemExit` from a step ends `sync` with that code, as `set -e` did.
- **The rendered profile's environment** (the shell did `source profile.zsh` so
  brew and system sync see its exports, e.g. proxy and certificate settings):
  a new service function runs
  `["zsh", "-c", 'source "$1" >&2 && env -0', "_", <rendered profile>]`
  through `Runner.run`, prints the result's stderr (the profile's own output,
  e.g. "loading macsetup profile") with `output.say`, parses the NUL-separated
  stdout into a dict, and the command applies it through a new
  `wiring.apply_environment(env: Mapping[str, str]) -> None` that does
  `os.environ.update(env)`. A non-zero exit is an `AppException` ("sourcing
    <profile> failed: <stderr>"), exit 1. Tests replace
    `wiring.apply_environment` with a recorder (add that to the autouse fixture
    in `tests/conftest.py`, so no test can change the real `os.environ`).
- **`RNFMAC_SYNC_PROFILES_ONLY`** (read from `wiring.environment()`) keeps its
  meaning: after the profile environment is loaded, info
  "RNFMAC_SYNC_PROFILES_ONLY set — skipping brew and system sync", exit 0. Add
  it to the names the autouse fixture deletes.

## Current behaviour

`shell/commands/sync.sh:23` `execute`: note whether `config/` is missing;
`config/pull.sh`; if it was missing, the notice above and return; else
`profile/sync.sh`, `source profile.zsh`, the profiles-only check, then
`brew/sync.sh` and `system/sync.sh`. Specs: `tests/commands/sync_spec.sh`
(profiles-only run; pre-config migration clones without applying) and
`tests/commands/config_spec.sh:141` (sync keeps uncommitted config changes).
