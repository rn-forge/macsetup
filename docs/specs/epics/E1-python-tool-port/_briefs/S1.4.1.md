# S1.4.1 — rnfmac config pull, push and reset

Brief for
[S1.4.1](../F1.4-machine-changing-commands.md#s141-rnfmac-config-pull-push-and-reset),
at `143b1a6` (line references) on branch `feature/python-tool-port`.

## Goal

Port `shell/commands/config/pull.sh`, `push.sh` and `reset.sh` (with the helpers
they use from `config/lib.sh`) to `rnfmac config pull|push|reset` in the Python
package, beside the existing `config status`.

## Settled

- Messages, flags and exit codes are the shell's (port plan, Phase 3 table).
  Shell `log_success` → `console.success`, `log_info`/`log_notice` →
  `console.info`, `log_error` + exit 1 → `raise AppException(...)`.
- `pull` carries uncommitted changes across on a stash (CLAUDE.md invariant).
- Clone URL: `$RNFMAC_CONFIG_REPO_URL`, else
  `https://github.com/${RNF_GITHUB_ORG:-rn-forge}/macsetup-config.git`, read
  from `wiring.environment()` (both are already cleared by the test fixture).
- `push` with no flag uses the host name (`wiring.host(run)`) as the message;
  `-m/--message <text>` overrides it; an empty message is a usage error, exit
  2 as Typer reports it. (The shell printed its own usage line and exited 1;
  Typer's usage error replaces it.)
- `reset --force`. Without it, local changes print `git status --short` and exit
  1\.

## Current behaviour

- `shell/commands/config/lib.sh:19` `ensure_config_checkout`: clones
  `--quiet --branch main --single-branch <url> <config>` when the checkout
  path does not exist, then `require_config_checkout`.
- `lib.sh:55` `update_config_checkout`: `fetch --quiet origin main`; equal HEADs
  → return; HEAD not an ancestor of `origin/main` → error "macsetup config has
  local commits that are not on origin/main — reconcile <config> by hand";
  dirty →
  `stash push --quiet --include-untracked --message "rnfmac config update"`
  (info "holding local config changes aside while updating ...");
  `merge --quiet --ff-only` (on failure pop the stash, error "could not
  fast-forward macsetup config to origin/main"); info "updated macsetup config
  to <short>"; stash pop failure → error "local config changes conflict with
  origin/main — resolve the conflicts in <config>, then run 'rnfmac config
  push -m <message>'".
- `pull.sh:26`: ensure, info "Updating macsetup config ...", update, success
  "macsetup config is current (<short>)", then notice "local config changes
  are still unpublished — see 'rnfmac config status'" when dirty.
- `push.sh:47`: require; clean → error "macsetup config has no changes to
  publish"; update; `add -A`, `commit -m <message>`,
  `push --quiet origin main`; success "macsetup config published (<short>)".
- `reset.sh:45`: require; fetch; clean → `reset --quiet --hard origin/main`,
  success "macsetup config is already clean (<short>)"; dirty without
  `--force` → error "macsetup config has local changes that would be discarded
  — rerun with --force" plus the short status; with `--force` → hard reset,
  `clean --quiet -fd`, success "macsetup config reset to origin/main
  (<short>)".
- Python today: `services/config_status.py` has `require_config_checkout` (reuse
  it, do not copy it); `commands/config.py` registers only `status`.
  `rnfmac config pull` fails with Typer's "No such command 'pull'" (exit 2).

## Tests first

New `tests/test_config_sync.py`, porting `tests/commands/config_spec.sh:66-150`
(the pull/push/reset examples; the last one, "syncs over uncommitted config
changes", is `rnfmac sync`, S1.4.6 — skip it). Use the `sandbox` and `rnfmac`
fixtures; git runs for real against the local bare origin. Each fails before the
change with exit 2 "No such command".

- `test_pull_fast_forwards_a_new_remote_commit`: after
  `sandbox.push_remote_commit()`, pull exits 0 and the checkout's
  `shared/profile.zsh` contains "# remote update".
- `test_pull_preserves_uncommitted_local_changes`: a local edit plus a remote
  commit; pull exits 0, both lines present, the notice about unpublished
  changes printed, and `git stash list` is empty.
- `test_pull_refuses_a_divergent_checkout`: a local commit and a remote commit;
  exit 1, "local commits that are not on origin/main".
- `test_pull_clones_an_absent_checkout`: remove the checkout, set
  `RNFMAC_CONFIG_REPO_URL` to `sandbox.origin`; exit 0 and the checkout exists
  on `main`.
- `test_push_defaults_the_message_to_the_host_name`: a local edit; push exits 0,
  the origin's last commit subject is `testhost`.
- `test_push_uses_the_given_message` (`-m "hello"`, and `--message`).
- `test_push_rejects_an_empty_message`: `-m ""` exits non-zero, nothing
  committed.
- `test_push_with_no_changes_is_an_error`: exit 1, "no changes to publish".
- `test_push_lands_on_a_remote_that_moved_on`: a remote commit and a local edit;
  push exits 0 and origin has both commits, linear.
- `test_reset_refuses_without_force`: local edit; exit 1, "rerun with --force",
  the edit is still there.
- `test_reset_force_discards_tracked_and_untracked_changes`.
- `test_reset_is_a_no_op_when_clean`: exit 0, "already clean".
