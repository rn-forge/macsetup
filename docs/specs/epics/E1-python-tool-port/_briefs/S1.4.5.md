# S1.4.5 — rnfmac system sync and system init

Brief for
[S1.4.5](../F1.4-machine-changing-commands.md#s145-rnfmac-system-sync-and-system-init),
at `7db1454` on branch `feature/python-tool-port`.

## Goal

Port `shell/commands/system/sync.sh` (runtimes: python via uv, node via nvm,
java via SDKMAN) and `shell/commands/system/init.sh` (oh-my-zsh and plugins,
nvm, SDKMAN) to `rnfmac system sync` and `rnfmac system init [--force]`.

## Settled

Lead (reviewer) decisions, 2026-11-22, under the owner's go-ahead for Phase 3:

- **Invariant (CLAUDE.md):** a runtime version with no match, or one that fails
  to install, is logged and skipped; every runtime is still attempted; the
  command exits 1 at the end if anything was skipped or a runtime had no
  version list. No hard-coded fallback pin.
- **Init scope (port plan):** oh-my-zsh and its three plugins, nvm and SDKMAN,
  plus `brew install bash` (the nvm and SDKMAN installers run under Homebrew's
  bash). **Homebrew and uv are not installed by `system init`**: they move to
  the Phase 4 bootstrap. Drop `setup_homebrew`, `setup_uv` and
  `activate_homebrew`.
- **nvm and SDKMAN are shell functions**, so each call runs in a child zsh:
  `["zsh", "-c", 'source "$1" && shift && "$@"', "_", <init script>, <cmd>, *args]`
  (`~/.nvm/nvm.sh`, `~/.sdkman/bin/sdkman-init.sh`). Arguments are passed as
  argv, never interpolated into the script. Put this in one helper.
- **Node's installed version** is read with `nvm version <spec>` (`lts/*` for
  the bare `lts` spec) after the install, since a child shell has no
  `nvm current` state to carry over.
- **No tests for the commands themselves** (CLAUDE.md convention: they drive
  real installers over the network). The **pure logic is tested**:
  version-list merging and Temurin identifier resolution go in a new
  `domain/runtimes.py`, with `tests/test_runtimes.py`. The two service modules
  are excluded from coverage by adding them to `sonar_coverage_exclusions` in
  `.rn-forge/kiln/config.toml` and running `task kiln:apply` — the one
  sanctioned way to change generated files.
- Long-running installers go through `Runner.stream`; values the code reads
  (`nvm version`, `sdk list java`, `--version` lines) through `Runner.run`.
  The download-and-run installers keep the shell's fixed URLs and run as
  `["/bin/bash", "-c", "set -o pipefail; <the shell's pipeline>"]`.
- Messages keep the shell's text (`log_error` → `console.error`, and so on).
  `--force` on init removes and reinstalls as the shell does.

## Current behaviour

- `system/sync.sh:44` `read_runtime_versions`: shared then host
  `<runtime>-versions` from the config checkout; strip `#` comments and
  surrounding blanks, drop empty lines, dedupe preserving order; empty → error
  "no <runtime> versions configured — add shared/<runtime>-versions or
  hosts/<host>/<runtime>-versions to macsetup-config".
- `sync_python` (line 77): `uv python install <spec>` each; failure → error
  "python <spec> not available — skipping"; none installed → "no python
  versions were installed"; else `uv python install <first> --default`,
  success "python runtimes synced (default: <first>, \<python --version>)" —
  run `~/.local/bin/python --version` for that.
- `sync_node` (line 112): `lts` → `nvm install --lts`, else
  `nvm install <spec>`; error "node <spec> not available — skipping";
  `nvm alias default <first>`; success "node runtimes synced (default:
    <first>, \<node --version>)" (get the node version through the helper, e.g.
    `nvm exec default node --version`).
- `resolve_temurin_identifier` (line 155): a spec ending `-tem` is used as is;
  else the first line of `sdk list java` whose last `|`-field, trimmed,
  matches `^<spec>([.+]|-tem$)` and ends `-tem`.
- `sync_java` (line 175): `PAGER=cat sdk list java` once (set `PAGER=cat` in the
  child zsh's environment or script), resolve each, errors "no Temurin build
  found for java '<spec>' — skipping" and "failed to install java <id> —
  skipping"; `sdk install java <id>`; `sdk default java <first>`; success
  "java runtimes synced (default: <first>)".
- `sync_runtimes` (line 225) then success "System sync complete !" only when
  nothing failed.
- `system/init.sh`: see `setup_ohmyzsh`, `setup_nvm`, `setup_sdkman` and the
  closing messages ("System setup complete !", notice "behind a corporate
  network/Zscaler? run 'rnfmac brew relay'"). Plugins clone into
  `${ZSH_CUSTOM:-~/.oh-my-zsh/custom}/plugins/` (the shell got `ZSH_CUSTOM` by
  sourcing `.zshrc`; use the environment value or that default instead).
- Python today: `rnfmac system sync` / `init` exit 2 "No such command".

## Change

- **Change:** new `domain/runtimes.py`
  (`merge_versions(shared: str | None, host: str | None) -> list[str]`,
  `resolve_temurin(spec, listing) -> str | None`); new
  `services/system_sync.py` and `services/system_init.py`; register `sync` and
  `init` (`force: bool = False`) on `system_app` in `commands/system.py`;
  `.rn-forge/kiln/config.toml` `sonar_coverage_exclusions` +
  `task kiln:apply`; add both commands to the Phase 3 sentence of the
  Python-port paragraph in `docs/guides/commands.md` (no new section), saying
  init leaves Homebrew and uv to the bootstrap.
- **Leave alone:** `system doctor`; `Runner`.
