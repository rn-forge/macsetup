# S1.4.4 — rnfmac brew relay

Brief for [S1.4.4](../F1.4-machine-changing-commands.md#s144-rnfmac-brew-relay),
at `7db1454` on branch `feature/python-tool-port`.

## Goal

Port `shell/commands/brew/relay.sh` to
`rnfmac brew relay [--force|--reset|--regen]`, applying the Homebrew Remote
Relay from the packaged assets.

## Settled

Lead (reviewer) decisions, 2026-11-21, under the owner's go-ahead for Phase 3:

- **Invariant (CLAUDE.md):** every apply resets the Homebrew repo to its clean
  base and re-applies the packaged patches fresh; nothing is cherry-picked.
  Never hand-edit a patch file.
- **Homebrew prefix:** a new `Layout.homebrew_prefix` field, `/opt/homebrew` by
  default; `Layout.from_env` reads the test seam `RNFMAC_TEST_HOMEBREW_PREFIX`
  (the shell's seam name). Add it to the names the autouse fixture in
  `tests/conftest.py` deletes.
- **Payload paths are parameters.** The service takes the strategy file and the
  patch directory as `Path`s; the command resolves them from
  `rn_forge.macsetup.assets` (`asset("homebrew", ...)`) through
  `importlib.resources.as_file`, so `git apply` gets a real path. Tests pass
  their own directories.
- **`--regen` requires a git checkout:** the packaged patch directory must be
  inside a git work tree (`git -C <dir> rev-parse --show-toplevel` succeeds).
  It writes each `<basename>.patch` there, and, while
  `<toplevel>/shell/homebrew/patches/` exists, writes the same bytes there
  too, because `tests/test_assets.py` fails when the two copies differ.
- **Flags** are three booleans. `--force` with `--reset` is a usage error
  (`rn_forge.cli`'s usage error, exit 2, like any bad flag in the Python CLI);
  precedence otherwise is the shell's: regen, then reset, then force, then the
  default. `-h/--help` comes from Typer.
- **Errors** (the shell's `log_warning` + `exit 1`) are `AppException` with the
  shell's text (exit 1). Successes and notices keep the shell's text via
  `console.success`/`console.info`.
- **Subprocesses:** `git apply --3way` and `brew update` go through
  `Runner.stream` so git's conflict report and brew's progress reach the
  terminal; every other git call uses `Runner.run`. The relay commit uses
  `git -c user.name=rn-forge -c user.email=rn-forge@local commit -q -m "rn-forge: apply Homebrew remote relay"`.

## Current behaviour

`shell/commands/brew/relay.sh`, all git calls scoped with `-C <prefix>`:

- `ensure_compatible_system` (line 108): no prefix dir → "this system is not
  compatible with the Homebrew relay — <prefix> not found (Apple Silicon
  Homebrew installs only)".
- `ensure_homebrew_repo` (line 122): `rev-parse --show-toplevel` fails →
  "<prefix> is not a git repository"; its resolved path ≠ the resolved prefix
  → "<prefix> is not the root of its git repository (root is <toplevel>) —
  refusing to operate on it".
- `head_is_relay_commit` (line 165): `log -1 --pretty=%s` equals the subject.
- `reset_homebrew_to_clean_base` (line 173): relay HEAD → `reset --hard HEAD^`,
  else `reset --hard`; then delete the untracked
  `Library/Homebrew/download_strategy/remote_relay_curl_download_strategy.rb`.
- `apply_relay` (line 203): reset; copy the strategy file in; `apply --3way`
  each of `download_strategy.rb.patch`, `download_strategy_detector.rb.patch`,
  `vendor-install.sh.patch` (all attempted); any failure → warning "conflicts
  applying relay patches — see conflicted files above", reset, "reset Homebrew
  back to its clean base; regenerate patches with 'rnfmac brew relay
  --regen'", exit 1. Else `add` the three managed files
  (`Library/Homebrew/download_strategy.rb`,
  `Library/Homebrew/download_strategy/download_strategy_detector.rb`,
  `Library/Homebrew/cmd/vendor-install.sh`) and the strategy, commit, success
  "homebrew remote_relay applied".
- Default (line 232): relay HEAD → success "homebrew remote_relay already
  applied"; else notice "Applying Homebrew relay patches ..." and apply.
- `--force` (line 243): notice "Resetting and reapplying Homebrew relay patches
  ...", reset, `brew update`, apply.
- `--reset` (line 252): reset, success "homebrew remote_relay removed — <prefix>
  is on a clean upstream base".
- `--regen` (line 262): no checkout → "'--regen' requires a git checkout — run
  from the macsetup checkout"; relay HEAD → "<prefix> HEAD is the relay commit
  — regen must run against a clean-base worktree with your hand edits
  uncommitted. Run 'rnfmac brew relay --reset', hand-edit, then --regen.";
  else for each managed file write `diff --no-color HEAD -- <file>` to
  `<basename>.patch`, warning "no diff found for <file> — is it hand-edited in
    <prefix>?" when empty, success "regenerated <basename>.patch".

## Tests first

New `tests/test_brew_relay.py`, porting `tests/commands/brew/relay_spec.sh`.
Fixture: a git repo under `tmp_path` with the three managed files holding
`original: <path>\n`, one baseline commit (hermetic git identity is already set
by conftest), and `RNFMAC_TEST_HOMEBREW_PREFIX` pointing at it; a `FakeRunner`
scripting `("brew", "update")` → `Result(0)`. Each fails before the change with
exit 2.

- `test_rejects_force_with_reset` (exit 2).
- `test_a_missing_prefix_is_an_error`,
  `test_a_prefix_inside_another_repo_is_refused`.
- `test_reset_restores_managed_files_and_removes_the_strategy`.
- `test_conflicts_reset_to_the_clean_base`: the packaged patches cannot apply to
  the fixture; exit 1, the "reset Homebrew back to its clean base" message,
  managed files unchanged, no strategy file, HEAD still the baseline.
- `test_already_applied_is_a_no_op` (empty commit with the relay subject).
- `test_force_reapplies_even_when_applied`: `brew update` called, then the
  conflict path (exit 1).
- `test_regen_then_apply_round_trips`: copy the packaged patch dir into
  `tmp_path`, hand-edit the three managed files in the fixture, call the regen
  service with that dir, assert three non-empty patches; reset the fixture,
  apply with that dir; exit 0, HEAD subject is the relay subject, managed
  files hold the edits and the strategy file is committed. (Call the service
  directly; the regen checkout rule is tested separately.)
- `test_regen_refuses_a_relay_head` and `test_regen_requires_a_checkout` (a
  patch dir outside any git work tree).
