# S1.5.2 — retire the shell product and shkit

Brief for [S1.5.2](../F1.5-cutover.md#s152-retire-the-shell-product-and-shkit),
at `885fd38` on branch `feature/python-tool-port`.

## Goal

Make the Python `rnfmac` the only product in this repository: delete the shell
payload, its specs, tooling and release workflow, drop every shkit dependency,
switch the kiln release on, and rewrite the instructions and docs for
`bootstrap.sh` and the `task` verbs (port plan, Phase 4, steps 2, 3 and 5).

## Settled

- **Bootstrap line** (owner, 2026-11-23): bootstrap.sh is fetched from the
  default branch, not from a release asset (kiln's `tag-exists` release cannot
  upload extra files):
  `. <(curl -fsSL https://raw.githubusercontent.com/rn-forge/macsetup/main/bootstrap.sh)`.
  On a blocked network: copy `bootstrap.sh` and a release archive across,
  then `. ./bootstrap.sh --archive <file> --version <version>`.
- **First Python release** (owner, 2026-11-23): `version = "3.0.0"` in
  `pyproject.toml`, above the shell's last tag `v2.4.1`, so `self install`'s
  "latest release" is the Python one. The shell's root `VERSION` file is
  deleted.
- **Release job** (lead, 2026-11-23): in `.rn-forge/kiln/config.toml`, set
  `[ci] release = "tag-exists"` and delete the comment above it that says the
  shell ships through `shell.yml`; then `task kiln:apply` regenerates the
  workflow and tasks. Never hand-edit a generated file.
- **shkit leaves** (port plan, Phase 4, step 3): `system doctor` no longer
  checks for shkit; the `shkit` finding is deleted, not downgraded. The
  tooling's `self install` writes `env.sh`, so nothing here installs shkit.
- **Instruction files** (lead, 2026-11-23): `CLAUDE.md` keeps only its first
  line, `@AGENTS.md`. `AGENTS.md` keeps its kiln block (between
  `<!-- BEGIN rn-forge kiln -->` and `<!-- END rn-forge kiln -->`, untouched)
  and its package-name rule and `RNF_HOME` guardrail, and loses every mention
  of the shell product, `mise`, shellspec and Phase 4 being ahead. It gains an
  `## Invariants` section carrying, rewritten for the Python commands, the
  `CLAUDE.md` invariants that still hold: `system doctor` is presence-only;
  `system sync` skips and exits 1 at the end, with no hard-coded fallback pin;
  `profile sync` patches `.zshrc` before its `source $ZSH/oh-my-zsh.sh` line
  and patches both `.zprofile` and `.zshrc`; `sync` pulls config first and
  stops without applying when the checkout was absent; the relay patches are
  the single source of truth and are produced by `brew relay --regen`;
  `config pull` carries local changes across on a stash; `system init` and
  `system sync` have no tests by convention and are coverage-excluded; and
  `bootstrap.sh` keeps its top-level assignments at file top level and never
  uses `set -e` or `exit`.
- **Spec pages stay as written:** closed features, the port plan and
  `agentkit-alignment.md` describe history and are not edited.

  `tests/test_system_doctor.py:49,65-74` assert both findings;
  `tests/fixtures/config/shared/profile.zsh:5` sources shkit.

- Docs naming the shell product as current: `README.md`, `docs/index.md:6-7`,
  `docs/reference/index.md:7-9`, `docs/architecture/docs-system.md`,

  `docs/guides/development.md`.

## Change

- **Delete:** every path in the first bullet above.
- **Python:** remove the shkit check from `system_doctor.py` and its two test
  assertions (keep every other finding as it is); drop the shkit lines from
  `tests/support.py` and `tests/fixtures/config/shared/profile.zsh`; in
  `tests/test_assets.py`, remove the comparison with `shell/` and keep the
  checks that each named asset is packaged and readable through
  `rn_forge.macsetup.assets`. Test-file docstrings that say "Port of
  tests/…\_spec.sh" may stay.
- **Version and release:** `pyproject.toml` version `3.0.0`; the `config.toml`
  change above, then `task kiln:apply`; `task setup` refreshes `uv.lock`'s own
  entry.
- **`.gitignore`:** drop the `docs/reference/shell/` lines.
- **Instructions:** `CLAUDE.md` and `AGENTS.md` as settled above.
- **Docs:** `README.md` gives the bootstrap line, the blocked-network form, then
  `rnfmac system init` and `rnfmac sync`, and lists the `task` verbs for
  development; it no longer mentions `shell/`, `install.sh` or `mise`.
  `docs/guides/commands.md`: the install section becomes the bootstrap (both
  forms, `--force`); `upgrade`, `cleanup` and `version` are replaced by one
  short section on `rnfmac self` (`install`, `upgrade`, `uninstall`,
  `cleanup`, `status`, `doctor`, from `rn-forge-tooling`); the "Python port"
  paragraph is removed. `docs/guides/development.md`: `task` verbs only.
  `docs/architecture/runtime-layout.md`: `bootstrap.sh` in place of
  `install.sh`, and the tooling's layout (`macsetup/versions/`, `current`,
  `config/`, `profile.zsh`, `$RNF_HOME/bin`, `completions/`, `env.sh`) — read
  `.venv/lib/python3.*/site-packages/rn_forge/tooling/install/home.py` for the
  real paths, do not guess. `docs/architecture/remote-relay.md`: the patches
  live in `src/rn_forge/macsetup/assets/homebrew/`. `docs/index.md` and
  `docs/reference/index.md`: no shell product.
  `docs/architecture/docs-system.md`: no shell reference, `shdoc`,
  `gen-docs.sh` or `mise`; record in its history list that the shell reference
  was retired with the shell product.
- **Leave alone:** `bootstrap.sh` and `tests/test_bootstrap.py`; every generated
  file except through `task kiln:apply`; spec pages; the commands' behaviour
  apart from the shkit finding.
