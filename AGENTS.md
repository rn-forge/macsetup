# AGENTS.md

What this repository is, how to set it up and the conventions everyone follows
are in [README.md](README.md). This file holds what an agent needs beyond that.

## Rules

- macsetup is mid-port from shell to Python
  ([the plan](docs/specs/python-tool-port.md)). Until Phase 4 the **shell**
  `rnfmac` in `shell/` is the shipped product; the Python package in `src/` is
  the scaffold it is being ported into. Do not implement a later phase early.
- The shell product's repo map, code style, invariants and test conventions are
  in [CLAUDE.md](CLAUDE.md). Read it before touching `shell/`,
  `tests/*_spec.sh`, `scripts/` or `.mise.toml`; its invariants hold until a
  phase retires the code they describe.
- The Python side follows the kiln standard below: everything goes through
  `task`, and a generated file is changed through
  `.rn-forge/kiln/config.toml`.
- The package is `rn-forge-macsetup`, imported as `rn_forge.macsetup`; the
  command it installs is `rnfmac`, and the product directory under `$RNF_HOME`
  is `macsetup`.

## Guardrails

- Never run `rnfmac self install`, `cleanup`, `uninstall` or the shell
  installers against the real home. `$RNF_HOME` is exported in the owner's
  shell: set `RNF_HOME` (and `HOME`, for shellspec) to a scratch directory
  first. `self uninstall` removes the whole `$RNF_HOME/macsetup/` directory,
  including the `config/` checkout and `profile.zsh`.
- Do not edit `docs/reference/shell/`: it is generated by `mise run docs`.
- Do not commit, push or add dependencies without being asked.

## Do and don't

- Do: run `RNF_HOME=/nonexistent-guard mise run verify` for the shell product
  and `task validate` for the Python side.
- Do: ship assets (zsh theme, keybindings, Remote Relay patches) from
  `src/rn_forge/macsetup/assets/`, read through `rn_forge.macsetup.assets`.
- Don't: hand-edit a diff hunk in a Remote Relay patch; `brew relay --regen`
  produces valid ones (see CLAUDE.md).

## Examples

Adding an asset: put the file under `src/rn_forge/macsetup/assets/`, name it in
`tests/test_assets.py`, and run `task test`. Until Phase 4 the same file also
stays under `shell/`, and a test fails if the two copies differ.

## Story workflow

Work is planned in [docs/specs/](docs/specs/index.md). A story gets a brief
under its epic's `_briefs/`, is built on a branch, checked with `task validate`
(and `mise run verify` while `shell/` exists), and is closed by deleting its
brief.
