# AGENTS.md

What this repository is, how to set it up and the conventions everyone follows
are in [README.md](README.md). This file holds what an agent needs beyond that.

## Rules

- The Python side follows the kiln standard below: everything goes through
  `task`, and a generated file is changed through
  `.rn-forge/kiln/config.toml`.
- The package is `rn-forge-macsetup`, imported as `rn_forge.macsetup`; the
  command it installs is `rnfmac`, and the product directory under `$RNF_HOME`
  is `macsetup`.

## Guardrails

- Never run `rnfmac self install`, `cleanup`, `uninstall` or `bootstrap.sh`
  against the real home. `$RNF_HOME` is exported in the owner's shell: set
  `RNF_HOME` (and `HOME`) to a scratch directory first. `self uninstall`
  removes the whole `$RNF_HOME/macsetup/` directory, including the `config/`
  checkout and `profile.zsh`.
- Do not commit, push or add dependencies without being asked.

## Do and don't

- Do: run `RNF_HOME=/nonexistent-guard task validate`.
- Do: ship assets (zsh theme, keybindings, Remote Relay patches) from
  `src/rn_forge/macsetup/assets/`, read through `rn_forge.macsetup.assets`.
- Don't: hand-edit a diff hunk in a Remote Relay patch; `brew relay --regen`
  produces valid ones.

## Invariants

These look like bugs or gaps but are decisions. Don't "fix" them without asking.

- `system doctor` is presence-only: it checks that `uv`, nvm and SDKMAN exist
  rather than diffing installed runtime versions against the configured ones.
- `system sync` skips rather than aborts: a runtime version with no match, or
  one that fails to install, is logged and skipped, and the command exits 1 at
  the end if anything was skipped. There is no hard-coded fallback pin; at
  least one of the shared or host `<runtime>-versions` files must exist per
  runtime.
- `profile sync` patches `.zshrc` before its `source $ZSH/oh-my-zsh.sh` line,
  because `plugins=()` must be set before oh-my-zsh reads it. Both `.zprofile`
  and `.zshrc` get their own copy of the block, since non-login shells source
  only `.zshrc`.
- `sync` runs `config pull` first, so a freshly pulled Brewfile or version pins
  apply before the rest. If the config checkout was absent it bootstraps it
  and stops without applying.
- The relay patches are the single source of truth: `brew relay` resets Homebrew
  to clean and re-applies them every time. Valid patches need real context
  lines from Homebrew's current sources, which is what `brew relay --regen`
  produces.
- `config pull` carries uncommitted local changes across on a stash rather than
  refusing them.
- `system init` and `system sync` have no tests by convention, since they drive
  real installers with no mockable seam; Sonar excludes them from coverage.
- `bootstrap.sh` keeps its top-level assignments at file top level, because
  assignments made in a function of a sourced file vanish under zsh, and it
  never uses `set -e` or `exit`, since it is sourced into the caller's shell.
